## 11.1 Purpose

This chapter defines the governance arrangements for maintaining this Guide itself — including ownership, review frequency, change process, and version control. As the governing framework for model work within the bank, the Guide must itself be subject to rigorous governance.

## 11.3 Review Triggers

This Guide must be reviewed and, where necessary, revised in response to:

| Trigger | Review type |
|---------|------------|
| Passage of 12 months since last review | Scheduled annual review |
| Material change in applicable regulation or supervisory guidance | Triggered review |
| Significant change in the bank's model portfolio or strategy | Triggered review |
| Material finding from Internal Audit related to model governance | Triggered review |
| Identification of a systemic issue in the model lifecycle | Triggered review |
| Merger, acquisition, or significant organisational change | Triggered review |

---

## 11.4 Review Process

1. **Review initiation** — MRM initiates review; defines scope and team.
2. **Impact assessment** — assess what has changed (regulatory, operational, lessons learned) and what must be updated.
3. **Drafting revisions** — proposed changes drafted by MRM in consultation with key stakeholders.
4. **Stakeholder consultation** — circulate draft to model owners, validators, IT/MLOps, Compliance, and senior management for comment.
5. **Approval** — revised Guide submitted to approval authority.
6. **Communication** — changes communicated to all affected parties; training provided where significant changes are made.
7. **Version update** — Guide published with updated version number and effective date.
